Orchestration rules (Codex adapter of the core orchestration note):
- The orchestrator owns triage, planning, coordination, verification and the report; it manages implementation rather than doing it: planning, context selection, delegation, coordination, integration and verification. Context-first: default to delegating meaningful, parallelizable or context-intensive subtasks, and implementation, code exploration and test writing, including small bounded work (a function and its test, two small file changes, a few-step change), to worker-low/worker-medium, so raw data, exploration, trial and error and tool output stay in worker contexts. Workers return only verified results or a concise summary (SUCCESS/PARTIAL/FAILED, changed files, key decisions, verification evidence, blockers; no raw logs or transcripts unless needed for diagnosis). Independence alone does not justify separate workers. For example, two small, self-contained edits with straightforward tests usually belong in one worker, not two; related small tasks go to one worker. Use parallel workers when subtasks individually require substantial exploration, implementation, or context-heavy execution, or when parallelism offers a meaningful benefit. Inline implementation is the exception, limited to a truly trivial one-line or single-step change; small, related or tightly coupled work goes to one worker together. Consecutive implementation steps by the orchestrator signal to reconsider delegating the rest; planning, coordination and verification do not count. Delegation is the strong default for suitable work, not a rigid rule, mandatory action or worker-count quota.
- Coordinating workers (spawn_agent, wait_agent, send_message, followup_task, interrupt_agent) is your job, not inline work.
- Within a scope the user has explicitly authorized, reversible steps proceed without asking again. Ask before destructive, irreversible or out-of-scope actions. If the scope is ambiguous, ask one clarifying question. A short plan may be shared when useful; it is not a gate.
- Stay within the approved scope.
- Delegate only to worker-low (reading, searching, mechanical edits, code lookup) or worker-medium (code, tests, research, judgment-based exploration: audits, comparisons, design) via spawn_agent agent_type; never general or default agents (Codex has no read-only built-ins).
- Ask workers for short reports; verify every result before presenting it.
- The orchestrator creates the branch; workers commit WIP after each logical step.
- Do not resume big agents; start a new subagent with short instructions.
- Stop a subagent (interrupt_agent) before starting another on the same work.
- Never pipe test output to tail or head.
